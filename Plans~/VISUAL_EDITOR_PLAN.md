# RUITK Builder — in-Unity visual editor for `.uitkx` (port of the browser POC)

Status: **RESEARCH COMPLETE — implementation not started**

> Assembled 2026-08-14 on branch `feat/legacy-syntax-removal` (post-0.16.0, package `com.reactiveuitoolkit` 0.16.0, Unity floor `6000.2`). Facts were gathered by a five-way research sweep (Editor/HMR, Runtime/Shared rendering, `ide-extensions~/language-lib`, `ide-extensions~/lsp-server`, Unity integration/conventions) plus live machine probes, then **adversarially re-verified claim-by-claim by a second five-way pass** — every file:line cited below survived that pass or was corrected by it. Statuses are what the CODE shows. The interaction spec is the browser POC at `Plans~/ruitk-ui-builder-poc/`. Single campaign: no phased releases — internal build order only, nothing ships until the whole editor works.

## 0. Executive summary

1. The **live preview infrastructure exists and is proven** — `Editor/EditorRootRendererUtility.cs` mounts real fiber trees on any `VisualElement` (~40 editor windows use it), and any hand-built `VNodeHostRenderer` still self-joins `MountRegistry` (registration happens in `FiberRenderer`'s ctor, `Shared/Core/Fiber/FiberRenderer.cs:33,51`). The builder bypasses the utility to supply a **budgeted scheduler** (the editor scheduler's queues are static, shared, and unbudgeted), and the mount mechanics for arbitrary user components are real engineering (§2.1) — proven pieces, new assembly required.
2. The **compile loop exists** — `UitkxHmrCompiler.Compile` gives 50–200 ms swap — but making it buffer-driven is a **source-provider refactor, not one overload**: the compiler reads `.uitkx` text from disk at five distinct sites (§2.2). `CompileBatch` is dead code and stays dead (§4.3b).
3. **Full IntelliSense from day one is feasible via an LSP client**, with three corrections from verification: the `WorkspaceIndex` is disk-only (unsaved sessions are invisible to element/props/graph intelligence until VE-07 adds an overlay), diagnostics publish runs **synchronously per didChange** (the client must debounce, ~100–150 ms), and custom `ruitk/*` requests are greenfield protocol work (zero precedent in the server), albeit on a library that supports them.
4. The **two genuinely new engineering surfaces**: the pan/zoom semantic-zoom canvas (zero manipulator precedent repo-wide) and the `CodeField` colored-editable-text control. Both are front-loaded as VE-00 spikes.
5. The **language-access decision**: a second build of the language library under a distinct assembly name (`Ruitk.Language.Editor.dll`), Editor-only, listed in `precompiledReferences` together with a **committed Editor-enabled `System.Collections.Immutable` 6.0.0** (verified absent from Unity's script-compilation reference set — without it the reference is CS0012 on arrival). Distinct name avoids CLR identity collision with the analyzer copy HMR `Assembly.LoadFrom`s. One CS0433 collision exists (`Ruitk.Core.HookRegistry`) and is routed around via LSP (§2.4).
6. **Blocking gap found by verification**: language-lib has **no AST→text printer** — `AstFormatter.Format(string, string)` is its only public member and it re-parses its input. The "AST transaction → text" loop the whole editing model rests on requires **VE-14**, a new public printer entry in language-lib (the private emitters already do the work).
7. The **save/abort model** fits the machinery: LSP overlays for unsaved intelligence, source-provider HMR compiles for unsaved preview, and the save boundary is where the single domain reload belongs — the normal `UitkxChangeWatcher` path fires for the batched writes, untouched (and external-editor saves keep working while the builder is open).

## 2. Verified architecture map

### 2.1 Preview mounting
- `Editor/EditorRootRendererUtility.cs`: `Mount(VisualElement, VirtualNode, Action<HostContext> env = null)` (L33), `Render` (L65, alias), `Unmount` (L74). One `VNodeHostRenderer` per host (L15-16). Caveats verification added: `env` runs **only on first renderer creation** (doc L29-31) — not per re-mount; and `Unmount`'s `PumpNow()` (L93) drains the **shared static** editor queues, not a per-mount queue.
- `Editor/EditorRenderScheduler.cs`: all queues `static` (L12-18) — including `BeginBatch/EndBatch`, so a builder calling batch APIs on it would defer *every* editor mount's work; `Pump()` drains fully, no time budget (L159-173), no dedupe. → the builder uses its own budgeted `IScheduler`.
- Custom mounting is fully public: `RuitkBootstrap.CreateHostContext(ElementRegistry, FiberHostConfig, IScheduler, bool)` (`Shared/Core/RuitkBootstrap.cs:44`; scheduler honored via `Environment["scheduler"]`, read at `FiberReconciler.cs:88` et al.), `VNodeHostRenderer(HostContext, VisualElement)` public (`Shared/Core/VNodeHostRenderer.cs:16,22`), `UitkHostConfig` publicly constructible and defaulted when `hostConfig: null`.
- **Refresh provider (verification correction)**: `RefreshRuntime.RegisterRootRendererProvider` is wired **only in `UitkxHmrController.Start()`** (`UitkxHmrController.cs:252-253`, deliberately lazy); with no provider `PerformRefresh()` returns 0 (`RefreshRuntime.cs:704-706`). **The builder registers its own provider** (enumerating via `MountRegistry`, which is `internal` → Shared IVT below); double registration with HMR is idempotent-safe to design for (last registration wins — both enumerate the same `MountRegistry`).
- **Mount mechanics for user components**: resolve the generated type by reflection — primary route `[UitkxSource(path)]` (verified EMITTED: `CSharpEmitter.cs:261`, `ExportsEmitter.cs:107`, `HmrCSharpEmitter.cs:343`; the stored path is the absolute authoring-machine path → compare canonicalized, never `==`), fallback effective-namespace FQN. Do **not** filter on `IsPublic` (non-exported components are `internal`). Then — **critical ordering fix** — call `RuntimeHelpers.RunModuleConstructor(type.Module.ModuleHandle)` FIRST: the SG deliberately registers families in a `[ModuleInitializer]` on a companion class that reflection access does not trigger (`CSharpEmitter.cs:526-539`; HMR forces it for the same reason, `UitkxHmrCompiler.cs:3105-3112`). Only then build `Func<IProps, IReadOnlyList<VirtualNode>, VirtualNode>` from the stable public `Render(IProps, IReadOnlyList<VirtualNode>)` method group (verified emitted at `CSharpEmitter.cs:377-382`, designed for exactly this) and mount `V.Func(delegate)` — `ResolveFamilyForDelegate` (`V.Core.cs:82`) resolves the family. Generated props classes have implicit public ctors (`CSharpEmitter.cs:1841-1851`) → knob instantiation via `Activator.CreateInstance`. **After every preview compile, re-resolve the delegate from `HmrCompileResult.LoadedAssembly`** — a cached delegate into a stale HMR assembly mounts the old body on remount paths.
- `FiberConfig.TimeSliceMs`/`TimeSlicingEnabled` are process-global statics — no per-preview budget without an API addition (accepted for v1).

### 2.2 Hot-swap compile
- `Editor/HMR/UitkxHmrCompiler.cs` (`internal sealed`, ns `Ruitk.EditorSupport.HMR`): `HmrCompileResult Compile(string uitkxPath, string[] companionCsFiles = null)` (L288); swap = `ForceRunModuleInitializers` (L3112) → `Family.Register` → `RefreshRuntime.PerformRefresh()` (`RefreshRuntime.cs:671`). Result (`internal`, L3880) carries `LoadedAssembly`, `FamilyKey`, timings.
- **Disk-read sites (verification: five, not one)** — VE-05 must virtualize ALL of them behind a source provider (`Func<string, string>` + a virtualized exists-check), not add a single-string overload: own file `ReadTextWithRetry` L295; batch analogue L631; **imported peer `.uitkx` reads in `EmitCompanionUitkxSources` L1337 with a `File.Exists` gate at L1317 that silently skips never-saved buffers**; other-file directive parsing `ParseDirectivesForFile` L3503; `InvalidateCompilationForFile` L1473. Controller-side `SyncAssetCacheForHmr` (`UitkxHmrController.cs:1420`) also reads disk (`File.ReadAllText`, early-return on `!File.Exists`) — meaning buffer-only previews render **without `@uss`/`Asset<T>` entries added since the last save**; stated as a known preview limitation, resolved at Save.
- **Compiler instancing (verification)**: all cross-compile state is instance state (`_crossRefCache`, `_hmrAssemblyPaths`, caches — L173-232); the sole existing instance lives in `UitkxHmrController` (L220). The builder owns exactly ONE compiler instance of its own for buffer compiles. When HMR Mode is also active, two instances coexist on different content (buffers vs disk); families converge after Save because registration is global and last-write-wins.
- State preservation: fiber reuse by Family reference identity (`FiberChildReconciliation.cs:316-317`), hook state in `FunctionComponentState.HookStates` — VE-D7's knob semantics fall out for free.

### 2.3 Save path and the domain reload
- `Editor/UitkxChangeWatcher.cs`: `OnPostprocessAllAssets` (L72) resolves owning asmdef folders synchronously in the import callback, then defers via two `delayCall`s — `TriggerRecompile` (L104) and `UitkxAssetRegistrySync.SyncChangedFiles` (L108, runs regardless of the HMR gate; can itself `Refresh()` on first-time registry creation). `TriggerRecompile` (L111): HMR gate at L116 → `WriteTrigger` per folder → ONE `CompilationPipeline.RequestScriptCompilation()` (L130). **The watcher is deliberately untouched by this plan** — under save-only writes it fires only at Save (wanted) and for external writes (must keep working).
- `Editor/HMR/AssemblyReloadSuppressor.cs`: a `bool _active` idempotence guard over Unity's own counted `LockReloadAssemblies`/`DisallowAutoRefresh` APIs; `Unlock` schedules `AssetDatabase.Refresh()` on `delayCall`. Two independent instances nest safely on Unity's counters. Constraints verification imposed: (a) **exception-bracket it** (`using`/`try-finally`) — a leaked `Lock` freezes the domain permanently, and HMR itself has a known escape of this shape (`Plans~/archive/HMR_AUDIT.md:415`); (b) never hold it across an await or dialog; (c) **known defect D-HMR-B10** (`Plans~/REMAINING_WORK.md`) — the deferred `Refresh` can fire into a re-taken lock and queue imports; a second suppressor user increases exposure. Mitigation: builder takes the suppressor ONLY for the synchronous write batch, and **takes none at all when `UitkxHmrController.IsActive`** (HMR already holds both locks; a builder `Refresh` under HMR's lock has ambiguous batching semantics — avoided entirely by the guard).
- **HMR-active saves**: the HMR FSW sees the writes → hot swap, no reload; `TriggerRecompile` is gated off. SG catch-up is the existing mechanism: `UitkxHmrController.Stop()` clears `_active` **before** its suppressor `Unlock`, so the Stop-time refresh imports everything accumulated and the watcher then runs normally. This plan relies on that mechanism and states it; it adds nothing to it.
- **Immutable-package note (pre-existing, §8)**: an import event on an immutable-package `.uitkx` collapses to `anyDefaultAssembly = true` and writes a trigger into the consumer's `Assets/Ruitk` → reload. Not caused by the builder; recorded.

### 2.4 Language access — the second DLL
- The analyzer copy (`Analyzers/Ruitk.Language.dll`, meta verified: `RoslynAnalyzer` label, every platform disabled) cannot be a `precompiledReference`. The HMR reflection bridge covers exactly 15 members; formatter, semantic tokens, cursor context, diagnostics analyzer, `ScrubNonCode`, import graph are unreachable.
- **VE-04**: build the same sources a second time as **`Ruitk.Language.Editor.dll`** — a separate `dotnet build` invocation on `UitkxLanguage.csproj` with `-p:AssemblyName=Ruitk.Language.Editor -p:BaseIntermediateOutputPath=obj-editor/` (verified: `<AssemblyName>` is a plain property; **never** pass `-p:AssemblyName` to the SG csproj — global properties flow into `ProjectReference`s and would rename the SG). Nothing in language-lib is assembly-name-sensitive (verified: no IVT, no embedded resources, no name literals). Distinct identity avoids CLR collision with HMR's `LoadFrom` of the analyzer copy and Unity duplicate-name checks.
- Committed at `Editor/Plugins/Ruitk.Language.Editor.dll` with meta `isExplicitlyReferenced: 1`, Editor platform enabled only — **plus `Editor/Plugins/System.Collections.Immutable.dll` (6.0.0), same meta shape**. Verified necessity: language-lib's public surface returns `ImmutableArray<>` (`ParseResult`, `UitkxParser.Parse`), Immutable is absent from Unity's script-compilation reference set (probed 6000.2: not in `NetStandard/ref`, shims, or `Managed/`) → CS0012 without it; the editor Mono BCL ships **1.2.3.0**, five majors old, and HMR's already-loaded guard is name-only/version-blind — the VE-00 spike tests the 1.2.3.0-preloaded case explicitly. Second real dependency: **`System.Memory 4.0.1.1`** — present in Unity's netstandard shims (lesser risk, named here).
- **CS0433**: the DLL compiles in `Shared/Core/HookRegistry.cs` (single `Compile Include`, one public type `Ruitk.Core.HookRegistry`, verified no others; `HookSignatureAttribute` NOT linked; `IsExternalInit` is internal — harmless). Builder code never names `HookRegistry`; hook palette via `ruitk/hooks` (note: `AmbientHookNames` — 42 entries, both casings — is the better palette source than `CanonicalNames`).
- Skew policing: today's CI check is `::warning::`-only (`test.yml:114-124`). For this load-bearing pair, the language-lib diffs get **promoted to a hard failure**; `build-generator.ps1` builds both variants in one run.
- The builder asmdef with `overrideReferences: true` must enumerate **every** precompiled DLL it needs: `Ruitk.Language.Editor.dll`, `System.Collections.Immutable.dll`, and `Newtonsoft.Json.dll` if VE-Q5 resolves to the package dependency. The repo's only `precompiledReferences` precedent is `Ugui/Tests/Ruitk.Ugui.Tests.asmdef` (nunit) — cited as such; CICD/Diagnostics.Logs are precedent for the Editor-only *shape* only.
- **VE-14 (new, blocking-gap fix)**: language-lib gets a public AST→text printer — `AstFormatter` currently exposes ONE public method, `Format(string source, string filePath = "")` (instance method, `AstFormatter.cs:163`), which **re-parses its input**; all markup emitters (`SerializeJsxInline` et al.) are private. VE-14 adds `public string Format(ParseResult, string filePath)` (or a `UitkxPrinter`) that skips the internal re-parse — flowing into the analyzer DLL, the Editor DLL, the LSP, and the CI diff. Also verified and load-bearing: `Format` **silently returns its input unchanged** on parse errors, inline-JSX control flow, **multi-component files**, and empty component names (`AstFormatter.cs:178-221`) — the builder must treat "output == input on a dirty transaction" as a hard error, and VE-14's printer must define behavior for those cases. Formatting fidelity: `RoslynCSharpFormatter` is wired in the LSP but **never invoked** (`ICSharpFormatterDelegate` has zero call sites; documented as rejected in `ide-extensions~/docs/formatter-whitespace-indentation.md:461-468`) — so a local formatter produces byte-identical output to the LSP **provided it loads options via `ConfigLoader.LoadFormatterOptions`** (`uitkx.config.json`, tabs/indent) instead of `FormatterOptions.Default`. No Save-time LSP formatting round-trip (earlier drafts had one on a false premise).
- Facade contracts (verified signatures): `SemanticTokensProvider.GetTokens(ParseResult, string, HashSet<string>? knownElements, string?)` — instance; feed `knownElements` from the LSP index or every unknown-cased element renders as a token; `AstCursorContext.Find(ParseResult, string, int line1, int col0)` — 1-based line, 0-based column; `DiagnosticsAnalyzer.Analyze(...)` — instance, **never re-emits T1** — merge `ParseResult.Diagnostics` yourself.

### 2.5 LSP client backbone
- Server: stdio only, OmniSharp 0.19.9, only flag `--vs2022`. **Do not pass it** — corrected rationale: it injects static capabilities (harmless), but its injected `textDocumentSync.change: 2` (Incremental) **lies** — the handler is Full-sync and would corrupt on deltas — and it gates an unsolicited `uitkx/classificationOverrides` push. Broader corrected guidance: OmniSharp 0.19.9 advertises `null` for most providers regardless (the VSIX patch stream exists because of this) — **the Unity client ignores `InitializeResult.capabilities` and calls every method it needs blind** (the VS Code extension already does this for formatting, `extension.ts:172-176`).
- Send **`rootUri`** = the Unity project root, exactly (not `workspaceFolders` — never read by the server; and not a subfolder: reference discovery walks up, but the `Library/ScriptAssemblies` DLL watcher does NOT (`RoslynHost.cs:1729-1739`) — a subfolder root means stale Roslyn metadata after every Unity recompile).
- Runtime: net8.0 framework-dependent, `rollForward: LatestMajor`. Probed: Unity 6000.0–6000.3 bundle .NET **6.0.21** (cannot host), 6000.4 = 8.0.16, 6000.5 = 8.0.21 (host it). Chain: `$RUITK_DOTNET` → `.ruitk-local.json` `dotnetPath` (**both are NEW keys** — `.ruitk-local.example.json` today has only `npmPath`/`unityEditor`; update it) → Unity-bundled dotnet if `shared/Microsoft.NETCore.App` has `8.*`+ → system dotnet (`FindDotnet` precedent `UitkxTestRunnerWindow.cs:324`; gate-legal) → error naming all rungs.
- Sync: `TextDocumentSyncKind.Full` — full text per didChange, last-writer-wins. `DocumentStore` beats disk for peers and companions (three-rung: store → companion overlay → disk). `didSave` is a server no-op. **Client-side didChange debounce is mandatory (~100–150 ms)**: `DiagnosticsPublisher.Publish` runs synchronously inline per notification (parse + lower + analyze + strict-imports incl. asmdef disk walks), and completion blocks on `EnsureReadyAsync` (a full Roslyn workspace rebuild) — the server's 300 ms debounce covers only Tier 3. The repo carries two in-code post-mortems of exactly this starvation (`TextSyncHandler.cs:80-99`). → VE-R10.
- **Disk-only index (verification, load-bearing)**: `WorkspaceIndex.Refresh`/scan gate on `File.Exists` and read disk — unsaved sessions contribute nothing to `KnownElements`/`GetProps`/`GetPeerExports`/`GetImportEdges`. Under VE-D2 this would empty the typed menus for new/unsaved components. **VE-07 therefore includes a server-side index overlay** (DocumentStore-first reads in `WorkspaceIndex`, mirroring `ReadPeerSource`'s treatment), so `didOpen`/`didChange` alone keeps the index current for session files.
- Custom requests: the OmniSharp mechanism (`IJsonRpcRequestHandler` + `[Method]` + `.WithHandler`) is real but **greenfield here** — zero existing custom handlers; the `uitkx/classificationOverrides` precedent is a fire-and-forget server→client notification, i.e. the opposite direction. Graph assembly is also not free: `GetImportEdges` returns raw specifiers — the handler resolves them via `ImportResolver`. `ruitk/schema` re-serializes (the typed `UitkxSchema` has no raw-JSON accessor).
- Client watched-files: the server's only watcher is the ScriptAssemblies DLL watcher; VS Code's client library synthesizes `didChangeWatchedFiles` — the Unity client synthesizes it from an `AssetPostprocessor` (natural source; HMR precedent).
- Lifecycle: graceful first (`shutdown` request → `exit` notification → server's `WaitForExit`), PID-kill as the backstop; the PID is serialized in window state and killed-if-alive on rehydrate (stdin-EOF exit on domain reload is OmniSharp-internal behavior, asserted not verified — hence the kill).
- Server payload: the committed VS Code `server/` is **40 MB** (RID-agnostic publish + 13 satellite locale dirs). The Unity-channel publish adds `--runtime` per-OS or stays RID-agnostic, plus `/p:SatelliteResourceLanguages=en` — sized by a publish test under VE-Q1.

### 2.6 Typed-data sources
- `ide-extensions~/grammar/uitkx-schema.json` v1.2 — 72 UITK + 18 UGUI elements, 408/408 attributes carry type + description; `styleKeyValues` 25 keys; `structuralAttributes` 2, `intrinsicElementAttributes` 60, `uguiIntrinsicAttributes` 26, `directives` 4, `controlFlow` 8. **Version-gating correction**: the schema *model* supports `sinceUnity`/`deprecatedIn`/`removedIn` at element and attribute level, but the *data* today is sparse — element `sinceUnity` × 3 (GUIDField, MaskField, Mask64Field), attribute-level × 0, `deprecatedIn`/`removedIn` × 0, plus `styleVersions` × 3 and `unsupportedStyleProperties` × 1. Version-greying in menus is limited to that data; do not design UI that presumes dense annotations.
- `StyleKeys.cs` = 92 public const strings (version-gated block); `CssHelpers.cs` complete (incl. 8 `Filter*` under 6.3+); hooks via `ruitk/hooks` (`AmbientHookNames` 42 entries + `GetDocMap()` tooltips).
- Component props: LSP `WorkspaceIndex.GetProps` (`PropInfo { Name, Type, XmlDoc, Line }`, 1-based line), honoring `FunctionParam.ToPropSourceName`.
- `ElementRegistry` has no enumeration API → VE-16 adds `RegisteredNames` for schema-vs-runtime drift checks.

### 2.7 Source-location mapping
- Verified: no file/line on `VirtualNode`/`FiberNode`/`NodeMetadata`; `UitkxSourceAttribute` path-only; `#line` exists only in generated C# (both emitter families). `Family.Id` IS the FQN — but cite `CSharpEmitter.cs:109-112` (SelfFamilyKey), **not** `Family.cs`, whose XML doc stale-claims "simple type name" (§8). Namespace-less components produce bare-name keys → the FQN→file inverse is ambiguous there; the builder resolves via `EffectiveNamespace`/`NamespaceDerivation` (language-lib → VE-15 depends on VE-04).
- Preview→canvas selection: **no element→fiber reverse map exists** — `element.userData` holds `NodeMetadata` (internal, no fiber back-pointer). The route is walking down from the renderer's root fiber matching `FiberNode.HostElement` — root access and `MountRegistry` are internal → **`[assembly: InternalsVisibleTo("Ruitk.Builder.Editor")]` is required in BOTH `Editor/AssemblyInfo.cs` (new) and `Shared/AssemblyInfo.cs` (append)**. Component-level selection is exact via Family; element-level uses structural-path mapping (builder owns the AST and knows which directive branches rendered); emitter-tagged `_sourceLine` (mirroring `_family`) stays the reserve plan (touches both emitters + parity contract tests).

### 2.8 Window/menu/asset integration
- Menu root `Reactive UI Toolkit/` — 200/300/9000 taken, ~100 free for the builder.
- Double-click: `UitkxConsoleNavigation` has 8 `[OnOpenAsset]` handlers (4 per Unity generation; 4 of the 8 at priority -10000); `ResolveAndDispatch` (L271) runs a three-rung external-editor fallback chain with **no branch or preference** — VE-11 inserts the builder branch inside it behind an `EditorPrefs` choice, plus an `Assets/` context item.
- `.uitkx` are `DefaultImporter` assets; registry sync (`UitkxAssetRegistrySync`, internal — IVT) runs automatically on Save imports (its `delayCall` sits before the HMR gate); **GEN-2** (registry scans `Assets/` only) is the backlog item that bites package-resident saves — cited alongside GEN-3 (csproj AdditionalFiles Assets-only).
- **Ctrl+S (verification)**: Unity routes Ctrl+S globally; `SaveChanges()` fires only on close/quit prompts. The window intercepts the key itself while focused; same for Ctrl+Z (the session undo stack is NOT Unity `Undo` — capture per-window, never leak to global undo). Shortcut policy must avoid the user-configurable `UitkxHmrKeybinds` (global, EditorPrefs-stored).
- Window policy: `BuilderWindow` is single-instance per tree (`GetWindow` keyed by root); one shared `BuilderLspClient` process owned by a session-scoped service, not per-window.
- Persistence: `UserSettings/ReactiveUIToolkit/Builder/{sha1(rootFullPath):8}.json` in the CONSUMER project (no repo precedent — first use, deliberate; Unity's default project gitignore covers `UserSettings/`). Serializer note: `JsonUtility` cannot serialize dictionaries → config uses serializable arrays or the VE-Q5 JSON library. Never write under the package root (`RuitkPackagePaths` doc, verified).
- Save/abort UX: `hasUnsavedChanges`/`saveChangesMessage`/`SaveChanges()` (standard Unity API, zero repo precedent — stated as such) + explicit toolbar buttons.

## 4. The save/abort model, end to end

1. Open tree → sessions per member file; read-only flag from `PackageInfo` source. LSP `didOpen` per file (real absolute paths; the VE-07 index overlay makes unsaved content visible to element/props/graph intelligence).
2. Every edit = AST transaction → **VE-14 printer** (options via `ConfigLoader`) → buffer text → debounced `didChange` → preview recompile from buffers → hot swap → re-render, state preserved. Disk untouched; no AssetDatabase activity; no reload. Printer bail conditions are treated as hard errors, never silent.
3. Squiggles: T1 (`ParseResult.Diagnostics`) + T2 (`DiagnosticsAnalyzer`) locally, T3 via LSP push. Known preview limitation: `@uss`/`Asset<T>` references added since last save resolve only after Save (asset cache sync is disk-gated).
3b. Cross-buffer imports: the builder's single compiler instance compiles dirty buffers **per-file in import-graph order** — B before A — so B's assembly is in the instance's cross-ref registry when A compiles. `CompileBatch` is retired dead code (zero callers, zero tests, bails on hook/module files — the common import target) and is **not** revived.
3c. Read-only cards: no dirty state; Save skips with a notice.
4. Undo/redo: session-scoped buffer snapshots; window-captured keys; not Unity `Undo`.
5. **Save**: (HMR inactive) take a builder suppressor via `using` → write dirty buffers (+ `AssetDatabase.DeleteAsset`/`MoveAsset` for deletions/renames) → dispose → deferred `Refresh` imports the batch → watcher fires → trigger(s) + one `RequestScriptCompilation` → one reload at a user-intended boundary. "One import pass / one reload" is the **measured assertion of VE-06**, not an axiom (auto-refresh re-enables one frame before the deferred refresh — a split pass is possible and must show up in measurement, not in the field). (HMR active) **no builder suppressor**; the HMR FSW hot-swaps the saved files; SG catch-up happens at HMR Stop via the existing Stop-ordering mechanism. Post-reload: window rehydrates from serialized state, LSP respawns (PID-checked), sessions re-open clean.
6. **Abort**: buffers discarded, `didChange` back to disk text, preview recompiled from disk.
7. New files exist as sessions + LSP overlays until Save materializes them (then registry sync runs automatically). Transient diagnostics for imports of session-only files — **corrected list**: UITKX2300 (target not on disk); 2301/2326/2109/2110 when the target exists but its export lives only in a buffer; 2308 can misfire (asmdef lookup on a nonexistent path). The builder suppresses these client-side for known session paths (LSP-push copies only; the build-time analyzer copies vanish at Save, which is when they'd first be evaluated anyway). The VE-07 index overlay removes most of these at the root.
